# MediaBender

A desktop application for AI-assisted batch video transcoding using FFmpeg.

## Language

**Queue Item**:
A single video file entry in the Work Queue. A long-lived object that starts sparse (path only) and gets enriched over time with ffprobe metadata, AI-generated commands, and processing results. A Queue Item may be regenerated or reprocessed multiple times.
_Avoid_: VideoFile (implementation detail), file, entry

**Work Queue**:
The ephemeral, in-memory collection of Queue Items currently being worked on. Not a persistent project — it can be saved/loaded as JSON for resumable sessions, but has no long-term identity.
_Avoid_: project, session, job

- The Work Queue lives in the Rust process and on disk (queue.json). The UI is a projection.
- Approved is enforced at Start Processing in Rust.
- Reset Status: Pending, is_approved=false, keep metadata and command_args.
- Regenerate: clear command fields and is_approved.

**Scan & Analyze**:
The operation that runs ffprobe on Queue Items with status Pending, extracting rich metadata and transitioning them to status Analyzed. Only operates on Pending items; already-analyzed items are skipped.
_Avoid_: scan, probe, inspect

**Generate Commands**:
The AI operation that produces an FFmpeg command, description, and reasoning for Analyzed Queue Items, transitioning them to status CommandReady.
_Avoid_: suggest, propose, auto-generate

**Status** (of a Queue Item):
The lifecycle state of a Queue Item. Three core states: Pending, Processing, Completed. Terminal states: Error, Skipped. Readiness for AI generation is inferred from the presence of `metadata`; readiness for processing is inferred from `is_approved: true`.
_Avoid_: state, phase, step

**Analyzed**:
An inferred condition of a Queue Item, not a status. A Queue Item is considered analyzed when its `metadata` field is populated with ffprobe results. The Scan & Analyze operation skips items that are already analyzed.
_Avoid_: scanned, probed

**Command Ready**:
An inferred condition of a Queue Item, not a status. A Queue Item is considered command-ready when its `generated_command` field is non-empty. The Generate Commands operation skips items that already have a command.
_Avoid_: ready, prepared

**Guidelines**:
The editable system prompt text that instructs the AI on transcoding rules, preferences, and constraints. Loaded from the user's existing notes and prompt files on first run.
_Avoid_: rules, instructions, prompt

**Provider**:
An AI backend configuration (base URL, API key, model). The app supports multiple providers; exactly one is active at a time.
_Avoid_: backend, endpoint, API

**Scan Root**:
The directory path explicitly selected by the user during Add Folder. Used to compute the relative directory structure preserved under the output folder. Each Queue Item remembers its Scan Root so output paths can be reconstructed at execution time.
_Avoid_: source folder, input root, base path

**Output Path**:
The destination file path for a transcoded Queue Item. When a folder tree is scanned, the output path preserves the directory structure relative to the Scan Root, anchored under the default output folder. For individually added files, the output path is simply the default output folder + naming template.
_Avoid_: output file, destination

**Approved**:
A boolean flag (`is_approved`) on a Queue Item indicating the user has reviewed and accepted the generated command. Only approved items are picked up by Start Processing. Reset to `false` when the command is regenerated by AI.
_Avoid_: signed off, accepted, confirmed

**Reset Status**:
The action of changing a Queue Item's status from Completed or Error back to Pending, so it will be picked up by the next Start Processing. Does not clear metadata, generated command, or description — only sets `is_approved: false`.
_Avoid_: restart, retry, revert

## Example Dialogue

> **Dev:** This file is showing as "Pending" but it already has metadata and a command. Shouldn't it be "CommandReady"?
>
> **Domain Expert:** No — "Pending" just means it hasn't been processed yet. Whether it's ready for AI generation depends on whether it has metadata. Whether it's ready for processing depends on whether it's been approved. The status itself only tracks the execution lifecycle.
>
> **Dev:** So if a user resets a Completed item, it goes back to Pending but keeps its metadata and command?
>
> **Domain Expert:** Exactly. Reset just means "run this again." The metadata doesn't change, and the command is probably still fine. If they want a new command, they use Regenerate, which clears the command and sets approved back to false.
>
> **Dev:** What if they add a folder, scan it, then add more files to the same folder later?
>
> **Domain Expert:** The new files get added as Pending with no metadata. Scan & Analyze skips the ones that already have metadata and only analyzes the new ones. Each item remembers its own Scan Root so output paths work correctly even if the queue has items from different source folders.

- "Reprocess" vs "Regenerate": Reprocess means execute the existing command again (resets to Pending → Approved → Processing). Regenerate means ask the AI for a new command (resets to Pending → Analyzed → CommandReady).
